## Correctness / latent bugs

### 1. Two promise caches poison themselves permanently on a single failure

`api/authors.ts:30` and `api/layoutSuggest.ts:12` both do:

```ts
promise ??= fetch().then((value) => { cache = value; return value; });
```

If that fetch rejects, the variable holds a *rejected* promise, and `??=` will
never reassign it because it isn't nullish. One transient network blip and
`gift`, `layouts <author>`, and every "did you mean…" suggestion stay broken
until the process restarts.

Neither cache has a TTL either, so layouts and authors created after boot are
invisible for the lifetime of the process.

### 2. Nothing invalidates the analysis cache after a mutation

`swap`, `setboard`, `addmagic` and `clearmagic` all change a layout's keys or
magic rules, and none of them calls `clearAnalysisCache`. The only invalidation
signal is `isCorpusCacheValid` (`mana2/cache.ts:70-76`):

```ts
if (layout.modified_at && entry.modified_at && entry.modified_at !== layout.modified_at) {
  return false;
}
```

Both sides must be present before it invalidates. If the single-layout endpoint
omits `modified_at`, edited layouts serve stale stats forever, silently.

### 3. Cache-file race between corpora

`computeAndCacheLayoutStats` (`mana2/cache.ts:172-185`) read-modify-writes one
JSON file per layout, but the `inflight` dedupe map is keyed `layout:corpus`
(`mana2/cache.ts:199`). Two different corpora for the same layout run
concurrently, both read the old file, and the second write drops the first
corpus's stats.

### 4. Internal error messages leak to users, with dead handlers below them

`commands/percentiles.ts:144-147` and `commands/debug.ts:367-370`:

```ts
if (error instanceof Error) {
  await replyEmbed(message, errorEmbed(error.message));
  return;
}

console.error(...);            // unreachable
await replyEmbed(message, errorEmbed("Failed to …"));
```

Every unexpected error — spawn failures, filesystem paths, JSON parse errors —
gets echoed into Discord, and the generic fallback beneath is unreachable.

### 5. `find` is a ReDoS hole

`mana2/corpusWords.ts:166` compiles a user-supplied regex and runs it against
every word in the corpus:

```ts
const regex = simple ? null : new RegExp(trimmed, "i");
```

`!dmini find (a+)+$` hangs the single-threaded bot for everyone. Worth a length
cap plus a timeout or a safe-regex check.

## Redundancy

### 6. The same catch ladder is copy-pasted ~12 times

`LayoutNotFoundError` → `LayoutApiError` → `error.message.includes("LAYOUTAPI_TOKEN")`
→ `console.error` + generic reply, in: `add`, `addmagic`, `clearmagic`, `copy`,
`gift`, `like`, `remove`, `rename`, `setboard`, `swap`. Ten files sniff the token
string; sixteen catch `LayoutNotFoundError`.

The token check is string-matching on an error message —
`requireLayoutApiToken` (`api/client.ts:6`) should throw a typed
`LayoutApiTokenError`. All of this belongs in one `runLayoutCommand(context, fn)`
wrapper.

### 7. Three pagination implementations

- `commands/magic.ts:21-43` — `clampLimit` / `clampPage` / `paginateRules`
- `commands/layouts.ts:42-100` — `clampLimit` / `clampPage` / `paginateLayouts`
- `mana2/examples.ts:106-163` — `clampExampleLimit` / `clampExamplePage` / `paginateExamples`
- plus a fourth clamp in `mana2/corpusWords.ts:235`

Same story for the "doesn't fit in a code block → retry at 15/20 per page → give
up" dance, hand-rolled separately in `magic`, `layouts` and `examples`.

### 8. Four separate finger enumerations that must stay in sync

- `layout/fingermap.ts:6` — `FINGER_FROM_DIGIT`
- `layout/fingermap.ts:19-43` — `FMAP_STANDARD` / `FMAP_ANGLE`
- `render/fingermap.ts:3` — `FINGER_IDS`
- `mana2/convert.ts:26` — `FINGER_INDEX` (the inverse of the first)

## Consistency

### 13. `errorEmbed(description, title)` is used three different ways

`commands/debug.ts:175` and `commands/debug.ts:331` pass
`("Usage", "Invalid cache subcommand")` — arguments swapped relative to
`debug.ts:41`, `addmagic.ts:54` and `gift.ts:133`, which pass
`("Missing X.", "Usage")`.

And in *every* one of those the first argument is discarded by the
`.setDescription()` chained immediately after. The signature invites this; a
`usageErrorEmbed(title, body)` helper would end it.

### 14. The last commit's fix landed in only one place

`47b9b20` switched `add.ts:44` to `resolveCommandName()`, but
`command/codeblock.ts:18` still compares the raw string:

```ts
if (space === -1 || body.slice(0, space).toLowerCase() !== commandName) {
```

So `addmagic` / `setboard` will silently stop matching the moment either gets an
alias.

### 15. `setboard.ts:103` inlines name normalization

```ts
const name = positional.join("-").toLowerCase();
```

That is exactly `normalizeLayoutName` from `layout/name.ts:33`.

### 16. Mutation contract varies by module

`layout/likes.ts` returns new objects. `layout/swap.ts:30` and
`layout/fingermap.ts:140,153` mutate in place *and* return the argument. Callers
can't tell which from the signature.

### 17. Naming collisions that will trip you up later

- `src/config.ts` (bot env) sits next to `src/config/` (user settings)
- `layout/fingermap.ts` vs `render/fingermap.ts`
- `listAllLayouts` (`api/layouts.ts:146`) doesn't paginate — it calls
  `listLayouts` with no limit, so `layouts --search` silently truncates at
  whatever the server default is

### 18. `command/index.ts` is vestigial

Only `bot.ts` uses the barrel; every command imports from
`../command/constants.js`, `../command/flags.js`, `../command/registry.js`
directly. Pick one convention.

### 19. Non-null assertions everywhere, but `noUncheckedIndexedAccess` is off

`tsconfig.json` has `strict: true` without `noUncheckedIndexedAccess`, so
`arr[i]` is already typed `T`, and none of the `!` assertions are required by the
compiler. They read as "I checked this" when nothing was checked. Either turn the
flag on and keep them, or drop them.

## Architecture

### 20. Corpus resolution spawns a subprocess every single time

`resolveDownloadedCorpus` (`mana2/corpus.ts:52`) → `listCorpora` →
`spawn(mana2-cli, "corpus")` + stdout parsing, with no cache anywhere.

A single cold `!dmini analyze` hits it up to **five** times before any real
analysis runs:

1. `resolveCorpus` (`config/user.ts:116`)
2. `getLayoutStats` (`mana2/cache.ts:198`)
3. `ensureCorpusPercentileCutoffs` (`mana2/percentiles.ts:176`)
4. `computeCorpusPercentileCutoffs` (`mana2/percentiles.ts:132`)
5. `getCorpusStatsIndex` → `resolveCorpusName` (`mana2/cache.ts:154`)

Even a fully warm run spawns it twice. This is the single biggest efficiency win
available: memoize the corpus list, and resolve the name once at the command
boundary so downstream functions take an already-resolved name.

### 21. Commands sit at the wrong altitude

Each `execute` does: arg parsing → flag error handling → fetch → ownership check
→ mutate → render PNG → build embed → five-branch catch. `"You don't own any
layout named …"` is written out seven times. The render-and-reply tail of `add`,
`copy`, `setboard` and `swap` is near-identical (~25 lines each).

A `withLayout` / `requireOwnership` pipeline plus a
`replyLayoutImage(layout, title, description)` helper would shrink
`src/commands/` substantially and make error behavior uniform by construction.

### 22. `command/flags.ts:25-127` is a hand-rolled if-ladder

Six near-identical "grab next token or throw" blocks, driven by
`ParseFlagsOptions` — a boolean interface that mirrors `CommandFlags`
field-for-field and must be updated in lockstep. A single
`{ name, aliases, kind }[]` spec table collapses this to ~30 lines and one
interface.

### 23. Speculative generality in `render/heatmap.ts`

`HEAT_RAMPS` has two ramps and `heatColor` takes a `ramp` parameter, but
`keyHeatColor` (`render/heatmap.ts:104`) always uses the default and nothing
plumbs a choice through — `ember` is unreachable. Either wire it into
`config palette` alongside the fingermap palettes, or drop it.

## Repo hygiene

- **No tests and no linter.** For a codebase with this much pure, easily-testable
  logic (`parseMagicRules`, `applySwaps`, `parseLayoutMatrix`,
  `buildPercentileCutoffs`, `searchCorpusWords`), that's the cheapest quality win
  on the list.
- **Three package managers' worth of state:** `package-lock.json` tracked,
  `bun.lock` untracked, plus the nix flake. Pick one and gitignore the rest.
- `mana2/cli.ts:73` hardcodes `/usr/local/bin/mana2-cli` as the fallback — worth
  pointing at the flake-provided binary, or failing loudly instead.
